### Project Overview

SyncCare is an end-to-end healthcare system I am building independently to explore how machine learning, medical information retrieval, document processing, and full-stack development can work together in a unified application.

The project is designed around four major capabilities: symptom-based disease prediction, a retrieval-augmented healthcare assistant, prescription image processing, and patient-doctor healthcare management.

The current implementation milestone is the **Random Forest disease prediction model**. The remaining modules—including natural language processing, medical knowledge retrieval, prescription OCR, and application-wide integration—are planned development stages rather than completed features.

The long-term objective is to bring preliminary disease prediction, contextual healthcare information, and everyday medical record management into a single application while maintaining clear boundaries between AI-generated information and professional medical diagnosis.

### Motivation & Problem

Healthcare information and personal medical workflows are often distributed across different tools. Patients may need separate systems for tracking symptoms, reviewing medical information, storing prescriptions, managing appointments, and remembering medication schedules.

At the same time, machine learning predictions alone provide limited value when they are not accompanied by clear context, appropriate uncertainty, and access to relevant supporting information.

SyncCare aims to explore these challenges through three connected areas:

1. **Preliminary Disease Prediction:** Use structured symptom and age inputs to predict a possible disease with a trained machine learning classifier.
2. **Contextual Healthcare Assistance:** Develop an NLP and retrieval-augmented generation pipeline that can retrieve relevant healthcare information and use that context to answer health-related questions.
3. **Centralized Healthcare Management:** Build patient and doctor workflows for medical records, appointments, prescription information, and reminders.

The system is being developed incrementally, beginning with the machine learning component before the supporting AI modules and application workflows are integrated.

### Disease Prediction Module

The disease prediction module is the first completed model-development milestone in SyncCare.

#### Model Approach

- **Algorithm:** Random Forest classifier.
- **Input:** Structured symptom indicators and age-related features.
- **Task:** Predict a disease label from the available input features.
- **Workflow:** Dataset preparation, feature processing, model training, and evaluation.

Random Forest provides a practical baseline for structured classification tasks. Its performance depends on dataset quality, class distribution, feature representation, and the evaluation methodology.

#### Evaluation Plan

The model's performance will be documented using suitable classification metrics, including:

- Accuracy
- Precision
- Recall
- F1-score
- Confusion matrix and per-class performance, where appropriate

Quantitative results will be added after the final evaluation figures are verified. No diagnostic accuracy or clinical effectiveness is claimed at this stage.

### Planned Module: RAG-Based Healthcare Assistance

The healthcare assistant is planned as a retrieval-augmented generation system for answering health-related questions using relevant reference material.

The intended workflow is:

1. Accept a user's health-related question.
2. Normalize and prepare the query.
3. Retrieve relevant documents from a curated healthcare knowledge base.
4. Supply the retrieved context to a language model.
5. Generate a response grounded in the available context.
6. Present supporting references when reliable source metadata is available.

This module is intended to improve the traceability of healthcare information. Retrieval alone cannot guarantee medical correctness, and the assistant will need safeguards against unsupported claims and misleading responses.

### Planned Module: Prescription OCR

The prescription-processing module is intended to convert uploaded prescription images into text that can be reviewed and organized within the application.

The planned pipeline includes:

1. Upload a prescription image through the application.
2. Store the image and obtain its reference URL.
3. Apply image preprocessing, such as resizing and noise reduction where appropriate.
4. Run OCR to extract text.
5. Process the extracted text to identify potential medication names, dosages, frequencies, and instructions.
6. Present extracted information for verification before it is used in healthcare records.

Handwritten prescriptions can be difficult to interpret reliably. Extracted medication information will require human verification and must not be treated as automatically validated medical instructions.

### Planned Module: Healthcare Management

SyncCare is intended to support separate patient and doctor experiences within the same application.

**Patient workflows**

- Manage profile information.
- View medical history and health records.
- Book appointments.
- Upload and review prescriptions.
- Set medication reminders.
- Access healthcare assistance.

**Doctor workflows**

- View patient records where authorized.
- Manage appointments.
- Add and review prescription information.
- Access consultation history.

These workflows are planned capabilities and will be implemented incrementally alongside the underlying backend and database integration.

### Key Engineering Decisions & Trade-Offs

#### 1. Random Forest as the Initial Classification Model

- **Decision:** Begin with Random Forest for structured symptom-based disease prediction.
- **Rationale:** It provides a practical baseline for tabular classification and enables systematic evaluation before exploring more complex approaches.
- **Trade-off:** Predictions depend on the quality and representativeness of the training dataset. Strong benchmark performance alone would not establish clinical reliability.

#### 2. Retrieval-Augmented Generation for Healthcare Information

- **Planned decision:** Separate document retrieval from language generation.
- **Rationale:** Retrieving relevant reference material can make answers easier to inspect and verify than relying exclusively on an LLM's pretrained knowledge.
- **Trade-off:** The quality of the final answer depends on retrieval relevance, source quality, model behavior, and correct attribution. RAG does not eliminate hallucinations.

#### 3. Modular Application Architecture

- **Planned decision:** Separate disease prediction, healthcare assistance, prescription processing, and healthcare management into distinct functional modules.
- **Rationale:** Each module has different inputs, processing requirements, and evaluation criteria.
- **Trade-off:** Integration requires consistent API contracts, data models, access controls, error handling, and validation across components.

#### 4. Relational Persistence with Prisma ORM

- **Planned decision:** Use Prisma ORM with MySQL for structured application data.
- **Rationale:** Patient profiles, appointments, prescriptions, and medical records benefit from explicit relationships and consistent persistence.
- **Trade-off:** Healthcare data requires careful authorization, privacy safeguards, and validation throughout the application.
